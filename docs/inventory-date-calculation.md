# 库存复购：按入库日期计算

## 计算规则

同一归一化商品使用自己的基础单位和有效消耗速度。购买记录同步与记录样本自动入库使用购买日期；手动入库使用填写的入库日期，未填写则为上海今日。

按日期排序，合并同日入库，逐段执行：

```
入库前剩余 = max(0, 上次库存 - 日均消耗 × 间隔自然日)
入库后库存 = 入库前剩余 + 当日入库量
```

最后计算到今日。同商品每天只扣减一次；断货期间不累计负库存。数量和速度均为 BigDecimal，计算不使用界面四舍五入后的值。每日不通过任务扣写数据库。

例：11月1日入5kg，11月10日入5kg，日耗0.2kg，11月18日预计剩6.6kg。

保存本周期每次入库日期和换算数量的最小快照，保证批量同步、分批同步、倒序同步结果一致。购买关联和请求键继续幂等，未勾选记录不增加库存；未勾选的有效购买仍可参与原有自动速度统计。

## 当前数量、重置与参数

- **确认当前库存**是实际数量，以确认日建立可信锚点，结束之前的输入周期，保留购买关联以防重复入库。
- 历史同步列表中购买日期小于或等于确认日的未关联记录标记为已被当前数量覆盖，不可直接累加。日期只有自然日精度，保守包含确认当天；确认之后记录样本产生的当天新收货和当天手动入库仍可增加。
- **重置库存**清空本商品本轮锚点、入库输入和购买关联，允许重新勾选历史重建；不删除购买记录、人工参数、价格或旧幂等请求。确认当前数量为0不等同于重置。
- 首次取得有效速度后，回推保留的历史入库。之后修改人工参数、切换方式或自动速度变化，从修改日分段生效，避免新参数推翻此前估算或人工确认数量。
- 若有正库存经过缺少可靠速度的历史区间，返回 `estimate_pending=true`，预计当前量和补货日期为空。原始入库合计在 `received_quantity` 中保留，不能将其冒充今日剩余。未知的人工锚点则保持库存未知，`estimate_pending=false`。
- 日历统一 Asia/Shanghai；同日不扣减，完整剩余天数向下取整。耗尽日期减去提前提醒天数得到提醒日期，已到期显示立即补货或超过预计耗尽日期。

## API 与前端

现有手动入库、记录样本、同步确认接口和请求字段保留。`receiptDate` 现在参与消耗起算，已超过人工确认日覆盖范围的旧入库会拒绝并回滚。

新增只读估算接口：

`POST /api/inventory/initialization/estimate`

```json
{"startDate":"2026-01-01","endDate":"2026-11-18","purchaseRecordIds":[101,102]}
```

不要求请求键，不创建档案、关联、预测缓存或请求占位。返回：

```json
{"products":[{"normalizedProductId":1,"normalizedName":"猫砂","unit":"kg","purchaseQuantity":10,"estimatedQuantity":6.6,"pending":false,"reason":"按已同步及本次勾选记录的入库日期估算"}]}
```

数量采用商品规则标准展示单位；`purchaseQuantity` 仅为本次尚未同步的勾选购买量，`estimatedQuantity` 包含同商品已有本周期库存。无可靠估算返回空值和原因。选择失效或ID无效返回400。确认时仍在事务内重新校验，不信任预览量。

库存详情新增 `estimate_pending`、`received_quantity`、`display_received_quantity`、`history_rebuild_required`。前端购买列表显示“购买入库量”，勾选后按商品显示同步后预计当前库存；快速切换选择不会展示过期响应。

## SQLite 升级与兼容

迁移文件：`src/main/resources/db/inventory-v1.0.2.sql`，由原 `InventoryMigration` 在启动时逐列检测并执行。扩展库存锚点字段、最小入库快照和速度分段两张计算表，不改变购买记录、价格或商品归一化。

升级前自动执行 SQLite `VACUUM INTO` 一致性备份，文件在原数据库旁，后缀为 `.inventory-v1-时间戳.bak`；失败则停止迁移。重启重复执行不会覆盖锚点或重复导入数据。

旧版本未保存完整手动入库和人工确认来源，无法可靠自动重建。迁移保留旧数量、日期及已用速度作为兼容基准，设置 `history_rebuild_required=true`。页面提示用户确认实际当前数量，或重置后勾选历史购买重建；不猜测覆盖旧库存。

后端代码及数据库迁移需要重启服务生效。升级后保留备份，若需回退，应停止服务后恢复整份迁移前数据库并使用旧版代码，不能只删除新增列。

## 范围与限制

购买日是默认入库日，运输和开封延迟未自动推断；可通过手动当前数量校准。已入库的日期、数量使用快照，修改或删除原购买记录不会静默改写该快照；需要重置重建或确认当前数量。少样本自动速度仍只是估算。当前没有可靠速度的历史缺口不会被伪造为零消耗。

未增加库存成本、批次、仓库或盘点流程，不生成虚假购买记录。本轮不生成交付ZIP。
